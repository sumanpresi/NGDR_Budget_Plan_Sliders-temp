Document alignment point: roadmap horizon

The roadmap horizon differs between the supplied documents. The presentation asks for approximately a 10-year data-growth scaling roadmap; the draft note asks for a 3–5 year roadmap. The final submission should use one agreed planning horizon. This page does not resolve the difference.

The one-minute explanation

Useful as speaking notes.

  1. NGDR's cloud is a rented office building for GSI's data. Instead of buying computers, GSI rents computing space from Amazon Web Services and pays a monthly bill.
  2. The current estimated AWS infrastructure spend is about ₹1.32 crore a year, covering the present load. The estimate does not describe dedicated connectivity, auto-scaling, tiered storage, a dedicated search layer, or a separately defined disaster-recovery / standby-site architecture.
  3. The note asks for a ceiling of ₹10–20 crore a year, not a fixed spend. It is room for BISAG-N to design against, with the final figure negotiated on technical merit.
  5. Anything above the priced requirements needs a separately defined justification. One possible additional capability is AI-assisted processing and search of legacy reports. If this is intended to be included, it should be separately defined, technically justified, costed and approved. It is not part of the draft note today.

Before the note goes up

Five points that would strengthen the proposal, and that ADG (PSS) or finance may well raise.

The internal costing of the ten requirements is well below the proposed ceiling

What would occupy the rest of the envelope is not yet defined

One possible additional capability is AI-assisted processing and search of legacy reports. If this is intended to be included, it should be separately defined, technically justified, costed and approved. It is not one of the ten requirements today, and this page does not present it as a justification for the ₹10–20 crore envelope.

A ceiling still needs a basis

“Evaluate on technical merit within a ceiling” is sound, but the ceiling itself will be questioned. The ten requirements priced out provide an initial planning basis. If additional capabilities such as AI are intended, they should be separately defined, justified and costed. BISAG-N's replies on server use, concurrent users and bandwidth would strengthen the basis further.

Pricing basis and region are not stated

The estimate uses pay-as-you-go pricing. Paragraph 4.2 already asks for savings-plan pricing on the steady load, which would lower the bill. Separately, the revised proposal should explicitly state the AWS region(s), the data-residency arrangement and the disaster-recovery region proposed for NGDR; the supplied documents do not specify them.

Some requirements cost nothing but must be written in

The uptime SLA, recovery objectives, quarterly capacity reviews, itemised billing and the right to renegotiate are contract terms, not AWS services. They add no cost and are among the most valuable things in the note, so they should appear in the agreement, not only in the covering letter.

Source and interpretation

Source basis. The current AWS cost figures are reproduced from the supplied AWS planning estimate. The ten infrastructure requirements are based on Section 4 of the supplied GSI draft note. The presentation is used for contextual comparison. Additional cost figures generated by this page are internal illustrative planning estimates and are not BISAG-N quotations.

Status of the ₹10–20 crore figure. It is a proposed budget ceiling / envelope in the draft note for FY 2027-28. It is not a committed expenditure, a guaranteed requirement, or a multi-year financial sanction.

Variability. Actual AWS billing may vary with usage, traffic, requests, pricing terms, support plan and applicable taxes.

Matters requiring GSI / BISAG-N confirmation.

  • Roadmap horizon: 3–5 years (draft note) or approximately 10 years (presentation).
  • The final annual budget envelope to be sanctioned.
  • AWS region(s), data-residency arrangement and disaster-recovery region.
  • BISAG-N's actual pricing for each of the ten requirements.
  • Whether AI-assisted processing, GPU capacity, or other GSI systems are to be included at all.
  • Actual SLA values: uptime, bandwidth and support response times.
  • Actual bandwidth requirement, measured from current usage.
  • Recovery point and recovery time objectives (RPO / RTO).
  • Log-retention requirements, to be confirmed against the applicable Government of India / CERT-In directions before being specified contractually.

Word list

The few technical terms that come up, in plain language.

Cloud / AWS
Renting computers, storage and internet capacity from a large provider instead of buying and running them.
Auto-scaling
The system adds computers automatically when traffic rises and removes them when it falls.
CDN
A delivery network that keeps copies of files near users, so downloads are fast across the country.
Read replica
A copy of the database used only for searching and browsing, so the main one stays free for uploads.
Tiered storage
Active reports on fast storage, older ones moved automatically to cheaper archive storage.
Direct Connect
A private line between GSI's network and AWS, instead of the public internet.
SLA
A written promise of service quality, such as 99.9% uptime, with remedies if it is missed.
DR (disaster recovery)
A spare, ready-to-run system, so the portal keeps working if one location fails.
GPU
A specialised processor that can substantially accelerate certain AI, image-processing and scientific-computing workloads compared with general-purpose CPUs.
GST
Goods and Services Tax at 18%, added to the AWS bill and support charges.
